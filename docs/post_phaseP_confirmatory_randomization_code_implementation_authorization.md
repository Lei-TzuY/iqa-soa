Authorizing code implementation authorizes **no** experimental act. The following remain unauthorized, without exception:

```

ACTUAL_MONTE_CARLO_SEED_GENERATION_AUTHORIZED: NO
ACTUAL_CONFIRMATORY_EXECUTION_AUTHORIZED: NO
```

Concretely, implementation sessions **must not** create:

```
results/confirmatory/<real-design-id>/
```

or any real instance of:

```
registration_draft.json
eligibility_manifest.json
registration_manifest.json
randomization_mc_provenance.json
assignment_manifest.json
final_analysis_manifest.json
```

Synthetic temporary fixtures under pytest-controlled temporary directories (e.g. `tmp_path`) are allowed and are the only permitted way to exercise these schemas.

Further, during implementation:

- **No real `design_id`** may be minted.
- **No real provider/model eligibility disposition** may be assigned. Every real provider remains `DESCRIPTIVE_ONLY_UNASSESSED` / `CURRENT_PROVIDER_ELIGIBILITY: UNASSESSED`.
- **No production assignment draw** (`secrets.randbits(1)` against a real registered matrix) may be performed for an actual experiment.
- **No production Monte Carlo seed** (`secrets.token_bytes(32)`) may be generated for an actual experiment.
- **No provider, model, or network endpoint may be contacted**, and no model inference may be performed, by implementation work.

Exercising `SecretsAssignmentRandomSource.draw_bit()` or the MC-provenance generator inside a focused test against a **synthetic** registration fixture in a pytest temporary directory is a test artifact and is authorized. Invoking either against a real registered confirmatory matrix, or persisting its output anywhere under `results/`, is not.
